# Agent 工作台开发与验证

日期：2026-09-18。前端仓库：`web-intelligent-integrated-interaction-platform`（本文路径均相对于仓库根目录）。

## 改造内容

主入口 `/agent` 按工作空间组织会话、知识库与评测。页面显示的是执行步骤、工具结果与状态，不展示模型隐藏推理。所有请求经 Java 转发或处理，浏览器不直连 Python，也不保存模型 Key。

事件客户端用流式 `TextDecoder` 保留不完整 UTF-8 字节，按 SSE 空行分帧；Pinia 以 `runId` 和递增 `seq` 隔离与去重。重连携带 `after` 和 `Last-Event-ID`，切换会话时取消旧连接，异步旧响应不能覆盖新选择。请求响应丢失后，相同任务提交复用同一 `clientRequestId`。

知识库上传使用 multipart，展示后端的真实处理阶段，不虚构百分比。文档原文先经过授权请求，再创建短期 Blob URL 预览；离开预览释放 URL。失败时展示后端错误，提供重试入口。审批使用服务端版本号与原始参数，不允许前端改写批准对象。

评测保存问题、可选预期文字和目标文档 ID，展示汇总与逐例结果；没有断言的样本显示“未评分”。费用仅包含 Agent 聊天运行的估算，不含文档向量化与评测调用；存在未知账单时显示“— / 费用待统计”，并注明已知部分。

Java 已受理但 Python 尚未建立运行时，页面显示“已提交，执行状态尚未确认”，每 2 秒查询提交回执，确认执行器已建立运行后才连接事件流。消息队列 `DELIVERED` 不代表执行成功；取消请求也要等待执行器确认。

经典页面保留，增加升级提示。修正旧 API 地址硬编码、HTTP 200 的 `Result.fail` 被当成上传成功、历史请求失败被吞成空数组、中文跨分块乱码和流读取失败被吞的问题。统一 JS/TS 路由与 Vite 入口；仅认证失效清理登录，短暂网络问题不强制跳登录页。

## 复现路径

1. 按 README 启动前端并连接 Java，使用独立测试账号登录。
2. 创建工作空间与知识库，上传可授权使用的 PDF，等待状态变为可检索；打开原文与提取内容。
3. 在助理中选择知识库发起提问，检查引用文档与页码；发起预约并分别验证批准、拒绝和取消。
4. 刷新页面并切换会话，检查历史、事件游标、审批状态与最终业务回执。
5. 新建评测批次，检查逐例答案、引用、耗时和费用未知的展示。

本次临时 Node 断言从标准输入执行，没有写入测试类；Playwright fixture、临时断言脚本和 fixture PDF 在验证后删除。用户原有 `tmp/` 和既有文件未删除。保留的截图位于 `output/playwright/`，`fixture` 与 `live` 文件名明确区分模拟接口与真实服务。中文合成语料 PDF 及两页渲染图保留在 `output/pdf/` 供复现。
